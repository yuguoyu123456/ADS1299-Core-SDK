# RL78 + ADS1299 Ready-to-Run Guide

This guide is additive only. Existing RL78 files remain intact.

## Integration

Reuse the existing `ads1299_port/` and board abstraction in this directory. Bind the generic ADS1299 callbacks to the RL78 CSI/SPI-capable peripheral and GPIO/interrupt implementation generated by Smart Configurator or used by the project, then add the shared Renesas ready-app and common ADS1299 core/profile sources.

## Peripheral setup

- SPI master, Mode 1 (CPOL=0, CPHA=1), MSB first.
- Start with a conservative SPI clock compatible with the selected RL78 system clock; 1–2 MHz is a practical first target if available.
- CS, RESET, PWDN and START as outputs.
- DRDY as falling-edge external interrupt input.

## Resource-conscious data path

RL78 devices are resource constrained compared with RA/RX families. Keep the DRDY ISR minimal and avoid floating-point conversion, logging or packet formatting in the sampling path.

Recommended flow:

`DRDY -> flag -> exact 27-byte ADS1299-8 read -> fixed ring buffer -> UART/host transport`

Use static buffers and explicit overflow counters.

## Validation order

1. Hardware reset ADS1299.
2. Verify device ID.
3. `RENESAS_ADS1299_PROFILE_INTERNAL_TEST`.
4. `RENESAS_ADS1299_PROFILE_INPUT_SHORT`.
5. `RENESAS_ADS1299_PROFILE_EEG_250`.
6. Confirm sustained frame alignment and transport headroom.
7. Add optional BIAS/lead-off only after stable baseline capture.

## Throughput note

Keep samples as raw signed 24-bit values on the MCU and move voltage conversion or advanced processing to a host when CPU/flash/RAM headroom is limited.

## 64-channel note

RL78 should not be treated as the primary synchronized capture engine for eight ADS1299 devices. For 64 channels, use FPGA or a substantially higher-throughput MCU/front-end and reserve RL78 for supervisory/control tasks if appropriate.

See `../DIRECT_USE.md` for the common Renesas integration flow.
