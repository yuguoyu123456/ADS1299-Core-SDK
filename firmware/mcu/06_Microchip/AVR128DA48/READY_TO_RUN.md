# AVR128DA48 + ADS1299 Ready-to-Run Guide

This guide is additive only. Existing AVR128DA48 files remain intact.

## MPLAB / MCC integration

Reuse this folder's current `ads1299_port/` and board abstraction. Bind the generic callbacks to the SPI/GPIO/interrupt code generated by MCC/Melody or used by the XC8 project, then add `../_shared/microchip_ads1299_ready_app.c/.h` and the common ADS1299 core/profile sources.

## Peripheral setup

- SPI master, Mode 1 (CPOL=0, CPHA=1), MSB first.
- Start around 1–2 MHz during first bring-up; increase only after the AVR clock configuration and frame timing are proven.
- CS, RESET, PWDN and START as outputs.
- DRDY as a falling-edge interrupt input.

## Resource-conscious acquisition

Keep the DRDY ISR extremely short. It should set a flag or notify the foreground/acquisition context. That context reads exactly one 27-byte ADS1299-8 frame and stores it in a fixed-size ring buffer.

Avoid floating-point conversion, printf and packet formatting in the real-time path.

## Validation order

1. Hardware reset ADS1299.
2. Read and verify device ID.
3. `MICROCHIP_ADS1299_PROFILE_INTERNAL_TEST`.
4. `MICROCHIP_ADS1299_PROFILE_INPUT_SHORT`.
5. `MICROCHIP_ADS1299_PROFILE_EEG_250`.
6. Run sustained capture and confirm frame alignment and transport headroom.
7. Add BIAS, lead-off and faster data rates only after baseline stability.

## Buffer/transport note

Use static buffers and explicit overflow counters. If UART is the final transport, verify baud-rate headroom before enabling higher sample rates. Prefer forwarding raw signed 24-bit values and converting to volts on the host.

## 64-channel note

AVR128DA48 should not be assumed to be the sole synchronized capture engine for eight ADS1299 devices. For 64 channels, use FPGA or a higher-throughput multi-SPI front-end and reserve the AVR for control/supervisory duties if appropriate.

See `../DIRECT_USE.md` for the common Microchip flow.
