# STM32G071 ADS1299 examples

Reference path: **NUCLEO-G071RB (STM32G071RBT6)** using STM32CubeG0 HAL.

Validation status: **TEMPLATE / repository integration present**. These sources are not yet recorded as STM32CubeIDE BUILD-VERIFIED or physical BOARD-VERIFIED.

## Recommended beginner entry point

Use:

```c
stm32g071_ads1299_beginner_demo(1000u);
```

Use `0u` only when you intentionally want continuous streaming.

The progressive demo performs:

1. platform/HAL binding;
2. ADS1299 hardware reset and `SDATAC`;
3. ADS1299-4/-6/-8 family ID probe;
4. internal-test capture;
5. input-short capture;
6. 250-SPS, gain-24 normal-input configuration;
7. continuous DRDY/read;
8. canonical 49-byte packet encoding and USART2/ST-LINK VCP streaming;
9. clean `STOP` + `SDATAC` when a finite frame count completes.

The original `main_ads1299.c` remains as a compatibility/minimal integration example.

## Files a beginner uses

- `../board/board_config.h` — single repository-owned board/pin/transport configuration point.
- `stm32g071_example_platform.c/.h` — STM32CubeG0 HAL binding. Normally only peripheral-handle binding changes when a different STM32G071 board/project uses different CubeMX instance names.
- `stm32g071_beginner_demo.c/.h` — progressive ADS1299 flow. Do not edit shared ADS1299 core files for first bring-up.
- `main_ads1299.c` — older minimal example retained for compatibility.

## CubeMX / CubeIDE configuration

Create or open an STM32G071RBT6 / NUCLEO-G071RB project and configure the peripherals used by `../board/board_config.h`:

- SPI1: master, 8-bit, MSB-first, **CPOL low / CPHA second edge (SPI Mode 1)**.
- SPI1 pins: PA5 SCK, PA6 MISO, PA7 MOSI.
- ADS1299 CS: PB0 GPIO output, idle high.
- ADS1299 DRDY: PC7 GPIO input for the blocking starter example; EXTI may be added later for production acquisition.
- ADS1299 RESET: PA9 GPIO output.
- ADS1299 PWDN: PA8 GPIO output.
- ADS1299 START: PB14 GPIO output.
- USART2: PA2 TX / PA3 RX, 460800 baud, 8-N-1 for ST-LINK VCP streaming.

Generate the Cube project normally. Do not copy invented startup files or linker scripts from this repository; use the files generated by the installed STM32CubeG0 toolchain for the selected device/project.

Add the STM32G071 model sources:

```text
firmware/mcu/01_STMicroelectronics/STM32G071/ads1299_port/ads1299_spi.c
firmware/mcu/01_STMicroelectronics/STM32G071/ads1299_port/ads1299_gpio.c

firmware/mcu/01_STMicroelectronics/STM32G071/examples/stm32g071_beginner_demo.c
```

Also add the shared ADS1299 core sources already maintained under:

```text
firmware/core_driver/ads1299/
```

The canonical stream encoder is shared infrastructure too. Add this source exactly once:

```text
firmware/common/data_packet/ads1299_packet.c
```

Add these include directories in CubeIDE:

```text
firmware/core_driver/ads1299
firmware/common/data_packet
firmware/mcu/01_STMicroelectronics/STM32G071/ads1299_port
firmware/mcu/01_STMicroelectronics/STM32G071/examples
firmware/mcu/01_STMicroelectronics/STM32G071/board
```

`ads1299_packet.h` defines the repository's canonical 49-byte packet and `ads1299_packet_encode()`; the model example intentionally reuses that shared implementation rather than duplicating framing or CRC logic.

## Expected serial progress

With wiring and Cube configuration correct, the text phase should contain messages equivalent to:

```text
ADS1299 STM32G071 beginner demo
OK ID ADS1299-8
RUN internal-test
OK internal-test frames
RUN input-short
OK input-short frames
RUN EEG 250 SPS config
OK EEG 250 SPS configured
RUN stream canonical packets
```

ADS1299-4 and ADS1299-6 report their matching ID string. Once binary canonical packet streaming begins, the serial stream is no longer purely human-readable text.

## Diagnostics

- `ERR RESET...` — check ADS1299 power, PWDN and RESET routing.
- `ERR SDATAC...` or `ERR ID...` — check SPI Mode 1, CS, MISO/MOSI/SCK, ADS1299 clock and power.
- `ERR DRDY timeout...` — check DRDY wiring and whether conversion has actually started.
- `ERR frame read...` — check SPI/CS integrity after DRDY.
- `ERR stream transport...` — check USART2/VCP configuration and baud rate.

## Small-MCU acquisition rule

The blocking HAL path is intentionally a first-bring-up example, not the final sustained acquisition architecture. On STM32G071, keep acquisition memory static and bounded. For sustained or multi-device work, use a short DRDY/EXTI path that places raw frames into a fixed-size ring/queue, records overflow, and lets non-real-time code perform packetization and UART/USB work. Avoid heap allocation and floating-point conversion in the acquisition timing path.

At 250 SPS, a 49-byte canonical packet requires 12,250 payload bytes/s. 115200-baud 8-N-1 provides only about 11,520 payload bytes/s, so the reference starter configuration uses 460800 baud.

## Moving to another STM32G071 board

Keep the shared ADS1299 core unchanged. Change only:

1. CubeMX pin/peripheral routing;
2. `../board/board_config.h` values;
3. `stm32g071_example_platform.c` handle names only if your generated Cube project names/instances differ.

If first bring-up requires editing `ads1299.c`, `ads1299_regs.h`, or `ads1299_model.c`, treat that as an integration defect rather than normal board porting.
