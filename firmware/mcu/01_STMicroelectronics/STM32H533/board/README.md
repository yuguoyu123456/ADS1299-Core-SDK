# STM32H533 ADS1299 board configuration

## Reference path

Use **NUCLEO-H533RE (MB1814, STM32H533RET6)** as the reference board for the standardized STM32H533 beginner path.

Edit only `board_config.h` for board-dependent pin/peripheral choices. The shared ADS1299 driver must remain unchanged for normal bring-up.

## Starter wiring

| ADS1299 signal | NUCLEO-H533RE MCU pin | Arduino header role |
|---|---:|---:|
| SCLK | PA5 | D13 / SPI1_SCK |
| DOUT / MISO | PA6 | D12 / SPI1_MISO |
| DIN / MOSI | PA7 | D11 / SPI1_MOSI |
| CS | PC9 | D10 |
| DRDY | PC6 | D9 |
| RESET | PC7 | D8 |
| PWDN | PA8 | D7 |
| START | PB10 | D6 |
| Host TX | PA2 | USART2_TX / STLINK VCP |
| Host RX | PA3 | USART2_RX / STLINK VCP |

Connect digital ground between the board and the ADS1299 hardware. Confirm that the ADS1299 DVDD / digital-I/O level is compatible with the Nucleo GPIO level before wiring. This repository does not define the analog front-end power, reference, BIAS/electrode safety, or patient-isolation design.

## STM32CubeH5 configuration

For the reference mapping:

1. Select `NUCLEO-H533RE` / `STM32H533RET6` in STM32CubeMX or STM32CubeIDE.
2. Configure SPI1 as full-duplex master, 8-bit, **CPOL Low / CPHA second edge (SPI Mode 1)**, MSB first.
3. Configure PA5/PA6/PA7 for SPI1 SCK/MISO/MOSI.
4. Configure PC9 as push-pull output for CS and initialize it high.
5. Configure PC6 as DRDY input; for interrupt-driven acquisition use falling-edge EXTI and keep the ISR short.
6. Configure PC7 RESET, PA8 PWDN and PB10 START as push-pull outputs.
7. Configure USART2 PA2/PA3 for the STLINK-V3EC virtual COM path when host logging/streaming is needed. `460800 8N1` is the starter transport setting in `board_config.h`.
8. Generate the vendor project, then bind the generated HAL handles/GPIO operations through `../ads1299_port/` rather than editing shared ADS1299 files.

Do not invent startup files or linker scripts from this folder; use the files generated by the selected STM32CubeH5 project/toolchain.

## Why 460800 baud

The repository canonical packet is 49 bytes. At 250 samples/s that is 12,250 bytes/s before any additional text logging. A conventional 115200-baud 8N1 UART carries only about 11,520 payload bytes/s in the ideal case, so it is not sufficient for an uninterrupted canonical stream. 460800 baud leaves practical headroom for the beginner path.

## Sustained acquisition rule

Blocking HAL calls are acceptable for initial probe/self-test bring-up. For sustained EEG acquisition, prefer:

`DRDY falling edge -> short ISR / timestamp -> bounded static queue or ring buffer -> frame handling -> packetization -> host transport`

Do not perform long UART/USB/network work inside the DRDY ISR. Count queue overruns explicitly. If SPI DMA is enabled, keep CS and frame boundaries deterministic and place DMA buffers in memory suitable for the selected H533 cache/DMA configuration; add cache maintenance only when the actual generated memory/cache configuration requires it.

## Another STM32H533 board

Keep the shared core and model port API unchanged. Normally only the board/config values and the vendor-project HAL binding should change: SPI instance/pins, CS/DRDY/RESET/PWDN/START GPIOs, clocks, and optional host transport.

## Primary board sources

Reference-board wiring should be checked against STMicroelectronics **UM3121, STM32H5 Nucleo-64 board (MB1814)** and the current NUCLEO-H533RE schematic/board-design files. UM3121 identifies NUCLEO-H533RE as MB1814 with STM32H533RET6, documents PA5/PA6/PA7 as Arduino D13/D12/D11 SPI1 signals, and documents the H533 ST-LINK virtual COM routing through USART2 PA2/PA3 for the relevant board configuration.
